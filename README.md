# Muse Windows

一个使用自有模型 API 的 Windows AI 工作台，提供聊天、文件参考和工作区管理。

这是独立、非官方的实现，与原 Muse 产品及其运营方没有关联。项目重新实现了部分桌面交互，不是原产品的完整克隆，也不包含原产品的账号、后端服务或安装包。使用时需要自行配置兼容的模型服务。

## 当前功能

- **聊天**：流式中文回复、停止生成、重试、Markdown 展示、复制，以及 Markdown / JSON 对话导出。
- **消息操作**：引用回复、点击引用回到原消息、逐条搜索与高亮定位、删除用户消息并保留占位，以及用 ↑ / ↓ 召回历史文本到草稿。
- **待发送**：回复尚未结束时可以继续提交消息，同一对话按顺序发送；可取消或恢复为草稿后修改。
- **整理**：搜索和置顶对话，创建、编辑工作区，并按工作区组织对话和参考文件。
- **文件参考**：导入或拖入文本、Markdown、代码、CSV、JSON、DOCX 和包含文字的 PDF，预览提取结果，并在聊天时引用。
- **文件编辑**：新建文本文件，多标签编辑、Markdown 预览、Ctrl+S 保存，以及未保存修改提示和保存冲突检查。
- **文件助手**：模型可列出、读取、新建和修改当前范围内的文件；写入前展示完整内容并逐次确认，执行记录随对话保存。
- **本地应用**：创建 HTML 或 React 小应用，编辑多文件源码、明确构建、切换最近构建、在独立预览中运行并保存应用自己的数据；可导出静态页面 ZIP。
- **应用工具**：助手可列出、读取、创建、修改和构建当前范围内的应用；源码写入与构建分别确认，并保留执行结果。
- **计划任务**：七种时间规则、时区预览、持久执行记录、立即运行和停止；每次结果保存为新对话。支持明确开启托盘后台和 Windows 登录启动。
- **计划工具**：助手可列出、读取、创建、编辑、暂停、删除及运行当前范围内的计划，涉及执行和更改时逐次确认。
- **知识与技能**：独立 MEMORY.md、中文关键词索引、知识快照、受限 Markdown 技能说明，以及逐版本授权和明确选择的聊天配置。
- **语音输入**：明确开启麦克风、音量和时长显示、停止审阅、丢弃或识别后发送；使用单独配置的语音识别服务。
- **声音与播放**：语音服务的声音试听，以及已有聊天音频附件的播放、暂停、继续和进度控制。
- **模型连接**：配置服务地址、模型名称和可选 API Key；支持模型发现、连接测试、系统提示词和温度设置。
- **本地数据**：保存聊天与文件副本，提供自动恢复备份，以及 JSON 备份导出和合并导入。
- **外观**：简体中文界面，支持浅色、深色和跟随系统主题。

## 在 Windows 上运行

需要 Windows x64、Node.js 24 和 npm。以下命令在包含 `package.json` 的项目根目录运行：

```powershell
npm ci
node node_modules/electron/install.js
npm start
```

安装依赖和 Electron 时需要联网。`npm start` 会先构建界面，再打开桌面应用。

首次启动后，打开“设置 → 模型连接”：

1. 填写兼容 OpenAI Chat Completions 协议的 API 地址。
2. 填写模型名称，或通过“获取模型”选择服务提供的模型。
3. 如果服务要求身份验证，填写自己的 API Key；本地免密服务可以留空。
4. 保存设置，再开始聊天。

API 地址支持服务根地址、`/v1` 前缀或完整的 `/chat/completions` 地址。例如：

```text
https://your-provider.example
https://your-provider.example/v1
https://your-provider.example/v1/chat/completions
http://localhost:1234/v1
```

根地址会自动补上 `/v1`。自定义路径前缀会保留。连接测试和模型发现只查询模型列表，不发起生成请求；若服务不提供模型列表，可手动填写模型名称。

### 使用文件助手

在工作区内打开对话，开启输入框旁的“文件助手”，然后提出需求，例如“读取工作区资料，整理一份总结保存为 summary.md”。模型服务需支持 Chat Completions 的 `tools` 和 `tool_calls`。

助手只能读取当前工作区与显式附件；普通对话不会列出其他未分组资料。新建或保存文件时，确认卡片会展示文件名和完整写入内容。每次“允许本次操作”仅授权这一项写入；拒绝、停止或切换该对话的工作区会取消等待中的操作。保存只更新工作台副本，并检查内容版本以防覆盖其他修改。已完成的操作记录在停止、重试、重启和备份恢复后仍会保留；停止不会撤销已经落盘的写入。

每次消息最多执行 8 轮、16 次工具调用，达到上限后会停止。新建于普通对话的文件在本次生成结束后，需要显式附加，或放入工作区，才能在后续消息中继续操作。文件工具不会执行命令或脚本。

### 引用、搜索和待发送消息

在消息下方点“引用回复”，可在输入框中检查、取消引用，发送后也能点击引用卡片回到原消息。搜索支持逐条消息匹配、分页及当前对话范围；选中结果后会滚动到对应消息并高亮。输入框光标在开头时按 ↑ 可召回历史用户文本，按 ↓ 返回当前草稿；这不会修改已经发送的消息。

删除用户消息前需要确认。删除后保留占位，清除该消息的正文、附件关联和引用摘录，同时清理自动恢复备份中的对应内容。其他回复、已经执行的文件操作、聊天标题以及以前手动导出的文件会保留；删除消息不会撤销文件写入。

模型回复期间继续发送的内容会进入“待发送”。同一对话等当前回复结束后再发送，其他对话可以独立进行；这适配的是本项目使用的 Chat Completions 接口。发送前会重新核对工作区和模型连接，若与入队时不同则停止等待。停止按钮也会取消该对话的待发送消息，未发送内容可恢复到草稿。队列仅在本次打开工作台期间有效，关闭后不会自动重发。队列最多保留 32 个正在发送或等待的请求，等待超过 5 分钟会停止；已经开始的请求不因这个等待期限而中断。网络请求发出后发生错误，不会自动重试。

### 语音输入

在“设置 → 语音输入”填写语音服务地址、识别模型和可选密钥。该服务需支持 [音频文件转写接口](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)：`POST /audio/transcriptions`，接收 `file`、`model` 和 `response_format=json`，返回 `{ "text": "识别文字" }`。根地址自动补上 `/v1/audio/transcriptions`，已有路径前缀会保留，也可填写完整接口。聊天模型和聊天密钥不会自动用于语音识别。

点击输入框的麦克风开始录音，每段最多两分钟。默认点“停止并审阅”将文字追加到草稿；“丢弃”取消本次录音或转写；点“识别后发送”、发送按钮或回车，会等识别完成后走普通聊天流程，保留当前工作区、文件和引用。也可在设置中明确开启停止后自动发送。识别期间若草稿通过其他入口发生变化，程序会保留新草稿、追加识别文字并改为审阅。

音频在本机转换为单声道 16 kHz、16 位 PCM WAV，停止时先释放麦克风，再发送到你配置的语音服务。识别请求不附带聊天或文件；转写后的聊天发送仍按普通对话规则附带资料。音频不会保存到聊天、磁盘或备份。切换输入框、改变相关范围或知识授权、修改模型连接、隐藏窗口及关闭程序，会取消当前听写；迟到结果不会写入其他草稿。服务错误不会自动重试。网络请求取消不能保证远端已经删除或停止处理音频，具体保留策略取决于你选择的服务。

此实现使用录音文件转写，尚未复刻原版实时 PCM 流、系统听写快捷键或实时通话。语音密钥由 Windows 单独加密，备份不包含密钥；导入备份保留本机的语音连接配置并关闭自动发送。桌面自动验收使用 Chromium 合成麦克风和本机模拟服务，不访问真实设备或外部语音 API。

### 声音试听与音频附件

在“设置 → 语音输入与声音”填写声音合成模型、声音 ID 和试听文字，然后点击“保存并试听”。使用同页的语音服务地址和语音密钥；不会使用聊天密钥。服务须支持 [声音合成接口](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create)：`POST /audio/speech`，接收 `input`、`model`、`voice`、`response_format=wav` 等字段并返回音频。完整的转写或声音合成地址会转换为同一服务前缀下的对应接口，不跳转其他站点。样句最多 4096 个 Unicode 字符和 16 KiB；返回音频最多 16 MiB，试听最多两分钟。修改样句、换声音、停止或关闭设置都会释放当前试听，迟到结果不会重新播放。试听请求不附带对话或资料，生成的音频与样句不写入聊天或备份。

把已有音频文件作为附件发送后，点击消息中的文件即可在本机播放，底部播放器提供暂停、继续、拖动进度和停止。切换对话、删除消息文字或删除对话会保留当前已选择的音轨，直到结束或手动停止；删除工作台内的源文件则会停止对应播放。试听和聊天音轨分别控制，听写期间也可手动暂停播放器。音频附件作为普通导入文件保存在本机及工作台备份中，播放不会把文件上传到语音服务，也不会自动转写或交给文本聊天模型。

可识别 WAV、MP3、OGG、M4A/MP4、FLAC、WebM 和 AAC 容器，实际解码取决于内置浏览器，无法播放时会显示错误。单个文件仍受 25 MB 限制，单轨最长两小时。自动桌面检查使用合成静音 WAV，并将应用输出明确静音；尚未验证真实扬声器、全部编码格式或外部声音服务。本地播放与独立的完整文件合成适配，不等同于原版的远端音频获取、原生 TTS 或 MP3 流式协议；尚未提供原版播客管理、声音技能目录及完整通话。

## 测试、构建和打包

```powershell
# 后端与主进程边界测试，使用本地模拟 API
npm test

# 构建桌面界面
npm run build

# 可选：启动 Electron，执行桌面流程验收
npm run test:desktop

# 在 Windows x64 上生成可直接运行的应用目录
npm run package:win
```

桌面验收会在 `test-results/` 中生成测试记录和截图，不需要真实模型 API 或密钥。[Windows CI 示例](docs/ci/windows.yml) 包含依赖安装、单元测试和界面构建，暂不执行动态桌面验收。示例尚未启用；如需在 GitHub 自动运行，请使用具有工作流写入权限的授权，将它保存到 `.github/workflows/ci.yml` 并提交。

打包结果位于 `release/Muse-Windows-<版本>-win32-x64/`，并使用 Windows 自带的 `tar.exe` 生成同名 ZIP。保留整个目录，双击其中的 `Muse.exe` 启动；运行打包版不需要另外安装 Node.js。打包脚本拒绝覆盖已有的同版本输出，再次打包前请移走旧输出或更新版本号。

### 可选的真实模型验收

```powershell
# 打开独立测试资料目录的设置页，填写地址、模型和密钥，保存后关闭程序
npm run test:live -- --configure

# 从 Windows 加密记录读取密钥，验证真实流式回复、多轮对话与工作区文件
```

此测试会调用你配置的模型服务并产生相应费用，只发送测试时生成的合成 TXT、DOCX 和消息。密钥通过应用设置输入，由 Windows 加密保存；命令参数和测试报告均不包含密钥。测试数据位于 `.test-tmp/live-provider-user/`，报告位于 `test-results/`，两者均已忽略，不会提交到仓库。

## 数据与 API Key

### 本地应用

在工作区中打开侧栏的“本地应用”，创建 HTML 或 React 项目。保存源码后点击“构建”更新预览；编辑中的源码与已成功构建的页面分别保留。保存与构建都会检查源码版本，发生冲突时保留草稿。最近三个成功构建可切换，失败构建不会替换已有页面。多页 HTML 可通过预览栏的页面选择器切换；预览中的相对页面链接暂不跳转。

React 入口为 `src/main.tsx`。支持 `react`、`react-dom`、`lucide-react`、`marked` 和 `dompurify`；图片等资源应通过 `import` 引用，或从导入的 CSS 中引用。JSX 中直接写相对图片地址或动态拼接地址不会自动打包，可能无法显示。构建只解析应用管理的虚拟文件，不读取本机任意路径，不安装依赖，也不执行项目脚本。

独立预览禁止联网、打开本机文件和嵌套外部页面。页面没有 Node.js、模型密钥或主界面的接口，仅通过受控通道读取和修改本应用的 JSON 数据。应用脚本仍可能运行较久；关闭预览会撤销数据通道。重新打开后数据保留，删除应用会移除源码、构建与应用数据。

页面可使用以下本地接口，`version` 是整个应用数据的版本，写入前应重新读取；冲突后不要盲目重试：

```js
await window.museArtifact.ready;
const current = await window.museArtifact.data.get('count');
await window.museArtifact.data.set('count', (current.value || 0) + 1, current.version);
const all = await window.museArtifact.data.list('');
await window.museArtifact.data.delete('count', all.version);
```

导出的 ZIP 包含已构建的静态页面，不包含应用数据或桌面数据通道；依赖此通道的功能只能在桌面预览中使用。导出工作台备份则包含应用源码、数据和最后一次成功构建。单应用最多 200 个文件、5 MiB 源码、5 MiB JSON 数据；单个数据值最多 256 KiB。不提供公开网址或云端托管。

### 计划任务

在侧栏打开“计划任务”，填写指令、工作区、重复规则和 IANA 时区，预览下次时间及绑定的模型服务，再明确确认。支持仅一次、固定分钟间隔、每小时、每天、每周、每月和每年。立即运行会额外执行一次，不会改变原定自动时间。

每次执行会把指令、所选工作区当时的文字资料及显式附件发送给确认的模型 API，可能产生服务费用。计划可以使用明确开启的只读资料工具，不能写文件、构建应用或创建更多计划。模型地址或名称变化后会暂停并要求重新确认；删除工作区或显式附件也会暂停受影响的计划。

默认仅在程序打开时运行。开启“关闭窗口后留在托盘”会隐藏窗口并继续执行，从托盘退出才停止。打包版可由用户另外开启 Windows 登录启动；不会在安装或首次运行时自动开启。电脑休眠或程序退出期间不会执行，恢复后每项错过的计划只补一次，并推进到下一个未来时间。固定间隔按 UTC 锚点计算；夏令时缺失时刻和不存在的月日跳过，重复时刻只取较早的一次。

执行前先保存认领记录，请求发出前再次检查授权和范围。失败、停止、超时或进程中断都不会自动重发该次请求；网络错误不能证明服务端没有处理。每项计划不重叠执行，全局最多两个同时运行，单次最多五分钟。可以保存最多 500 个计划，每项保留最近 100 次记录，全局最多 5000 次；已有结果对话独立保留。再次回复或重试计划结果对话会保留原执行记录所指的结果消息。

导出和导入的计划一律暂停，运行中的导出记录标为中断，导入会重新生成所有引用标识符。自动备份恢复也暂停计划并关闭后台偏好，避免旧记录恢复后重发。确认规则和范围后才能重新启用。删除计划保留执行记录与结果对话。

提醒会显示在工作台，并尝试系统通知；后台托盘提供气泡提醒回退。系统通知显示仍受 Windows 设置与应用注册影响，便携包不保证通知中心送达，相关安装条件见 [Electron 官方说明](https://www.electronjs.org/docs/latest/tutorial/notifications)。测试不修改系统登录启动项，也不向用户显示合成系统通知。

### 本地数据与密钥

聊天、工作区信息和导入文件的副本保存在本机应用数据目录。删除应用内文件会移除受管理的副本，不会删除原始文件；删除工作区会将其中的对话和文件转为未分组，并暂停受影响计划。

在“工作区 → 新建文件”中可以写作，或打开已导入的 UTF-8 文本副本后编辑。编辑内容必须不超过 1 MiB 和 200,000 字符；被截断的预览、DOCX、PDF、UTF-16 和二进制文件保持只读。保存会校验打开时的内容版本；有其他修改时会提示冲突并保留当前草稿。保存更新文件副本、提取缓存和后续聊天上下文，原始导入文件不变。文件编辑带有中断恢复记录。

发送消息时，应用会向**你配置的模型 API**发送系统提示词、对话内容，以及当前工作区资料和显式附件中提取、截取的文字。文件内容作为参考数据处理，代码附件不会在应用内执行。模型服务如何保存和处理这些内容，取决于你选择的服务。项目不使用原 Muse 的账号、凭据或服务接口。

API Key 由 Electron `safeStorage` 加密保存，在 Windows 上使用 DPAPI 保护；保存后的密钥不会回传给界面，也不会写入聊天导出或数据备份。系统加密不可用时会拒绝保存新密钥，不会退回明文保存。迁移到其他设备或 Windows 用户后，需要重新填写密钥。

聊天记录和文件副本本身以明文保存在本机。导出的 JSON 备份也包含聊天和文件数据，请按资料的敏感程度保管。备份导入会校验格式、文件大小、校验值和引用关系，重新生成标识符，再合并到现有数据；不会采用备份中的文件系统路径，也不会覆盖本机 API Key。

### 知识、长期记忆和技能说明

输入框上方的“知识与技能”管理当前范围的资料。`MEMORY.md` 是长期记忆文档，与知识条目的搜索索引分别保存；它不会自动写入知识索引。知识条目支持中文和 Unicode 关键词检索，保存后须明确“重建索引”；尚未构建、内容已变化和构建失败都会单独显示。这是独立的本地关键词实现，未恢复原版语义检索、嵌入或自动记忆整理算法。

聊天配置可包含自定义说明、最多 50 份知识快照、当前范围的长期记忆文档和最多 50 项技能说明。快照由程序读取所选知识、文件、对话或应用源码后生成，每份最多 8192 个 Unicode 字符；源内容更新后保留旧快照，须点击刷新才能替换。直接勾选 `MEMORY.md` 则每次使用文档的当前版本。确认配置后，在输入框上方选择它；已有对话可以预览将发送的知识。没有选择配置的聊天不会自动附加知识或技能。所选上下文总计最多 65536 个 Unicode 字符，超出时会明确拒绝发送。

技能导入接受受限的 `SKILL.md`，仅解析 `name`、`description`、`version`、可选的 `manifestVersion: 1` 和 `toolRequirements` 等扁平元数据以及 Markdown 正文。它不执行脚本、不安装依赖。未知工具要求会使技能不可用；已知要求也只表示使用条件，不会开启任何工具。技能须明确授权当前内容、版本、范围和工具要求，修改内容会撤销原授权。聊天配置默认只允许读取资料；选择工作区助手范围后，本次聊天仍需另外开启助手，写入仍逐项确认。

助手另有六个记忆工具：搜索、读取、创建、修改、删除及重建派生索引。未分组聊天只能访问配置中明确选择的知识条目和本轮新建条目，不能列出全部未分组知识；未分组完整索引由界面明确重建。索引使用 CPU 在本机生成，不调用嵌入服务。后台计划暂不绑定聊天知识配置。

修改活记忆文档、所选配置或技能授权，会停止使用旧上下文的回复和待发送消息。删除源资料会清除关联的派生知识、快照及自动恢复副本，并要求重新确认受影响的配置；已有聊天文字和以前手动导出的文件仍会保留。自动重发历史工具记录时，不附带旧记忆正文或旧记忆写入参数。

数据备份包含知识、技能说明和配置。导入时重新映射标识符，技能停用且授权清空，配置须重新选择技能并确认；派生索引可以重建。同一未分组范围只能有一份 `MEMORY.md`：内容相同会复用本机文档，内容不同会原子拒绝导入并保留现有资料，请先保存两边备份再整理冲突。工作区随导入新建，不会覆盖已有工作区的长期记忆。

## 当前限制

- 目标平台为 Windows x64；暂未提供安装向导、代码签名和自动更新。
- 模型服务需要兼容 Chat Completions；尚不支持仅提供 Responses 协议的接口。助手提供四种文件工具、五种应用工具、七种计划工具和六种记忆工具，未覆盖原产品的完整节点与远程 Agent 能力。
- 模型列表查询不受所有服务支持，连接测试通过也不代表每个模型都可调用。
- 单个参考文件最多 25 MB；JSON 备份最多 150 MB。较长文件和对话会按上下文预算截取，不会把所有资料完整发送给模型。
- PDF 仅提取已有文字，不包含 OCR。加密、损坏或不支持的文档会显示提取失败或不支持；DOCX 仅提取主要正文、脚注和尾注文字，不保留完整排版。
- 数据保存在本机，暂不提供账号登录、跨设备同步、多人协作、实时语音或远程电脑控制。本地计划不替代原版云端调度器；Goals、完整自动写入审批与远程执行仍未实现。已发送消息暂不支持原位编辑；可召回文本修改后作为新消息发送。
- 不连接原 Muse 的云端功能，不能直接迁移原产品的账户或私有云端数据。

完整目标的现状与后续工作见 [重建进度](docs/reconstruction-status.md)。已枚举的原客户端接口也不等同于已完整恢复所有行为。
