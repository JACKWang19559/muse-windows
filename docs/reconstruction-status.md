# 重建进度

目标是继续分析原 Muse 8.0 客户端，并在 Windows 上恢复其功能。完整目标仍未完成；当前版本是可运行的独立客户端。

## 当前可运行部分

- 自有 Chat Completions 服务、流式聊天、停止和重试。
- 本地聊天、工作区、文件上下文、导出与备份恢复。
- 新建文本文件，多标签编辑、Markdown 预览、保存冲突保护及编辑中断恢复。
- 模型文件工具循环：列出、读取、新建、保存；逐次确认写入，保留执行回执，支持拒绝、停止和恢复。
- 回复引用与快照、用户消息删除占位、逐条消息搜索分页及精确定位、历史草稿召回和本次会话内的待发送队列。
- 本地 HTML/React 应用源码、离线构建、最近三个构建历史、隔离预览、应用范围内的数据 CAS、静态页面导出和备份恢复。
- 应用与普通聊天并排使用，发送时保留当前应用引用；排队、失败恢复和历史回放区分应用标识与工具授权。
- 五种模型应用工具，逐次确认创建、源码写入及构建，并保留已提交操作的回执。
- 七类本地计划规则、时区计算、持久认领和结果记录、后台只读执行，以及模型管理计划工具。
- 托盘后台偏好、登录启动选项、提醒、导入暂停，以及取消退出后继续编辑的生命周期处理。
- 独立长期记忆文档、中文关键词倒排索引、明确捕获的知识快照、技能说明和版本授权、聊天配置与上下文变更检查，以及六种记忆工具。
- Windows 密钥加密、受限界面桥接与外部链接检查。
- 独立语音服务配置、单声道录音、停止审阅、取消和识别后发送；范围或授权变化后撤回听写，拒绝迟到结果。
- 声音试听与已有聊天音频附件分别播放，暂停、继续、拖动进度、跨路由控制及有界音频资源释放。
- 本地模拟服务的后端和真实 Electron 桌面验收，以及可选的真实模型验收工具。

## 原版证据与边界

静态分析已从原客户端枚举 125 个桥接动作、337 个声明路由和 76 个原生回调属性。这些是有界清单，既不是完整行为总数，也不是已完成实现的数量。原包包含的前端和 ARM64 原生部分已在 Windows 上分析；原 macOS 程序尚未执行，原服务端代码不包含在安装包中。

第二轮恢复了文件编辑的状态与保存流程、回复引用、搜索历史窗口、消息队列重试，以及 Space 和工具调用的部分协议。Swift 元数据进一步确认了本地动作规格、参数规格与基本参数类型。原界面中的“新建共享 Agent”存在已退役门控，不能将静态方法的存在当成实际可用功能。

0.3.0 根据已恢复的动作规格结构实现了独立的参数校验、能力声明和本地文件工具执行。接入自有模型服务的循环、权限名称、次数限制和逐次确认规则是本项目的实现选择，不能视作原版完整协议的复刻。原生调度、远程节点和原版权限规则仍在分析中。该版本通过 134 项后端/宿主检查及 43 项 Electron 桌面检查，使用本机模拟模型服务。

第四轮进一步恢复了引用参数、消息搜索和历史窗口、删除占位、输入框历史召回，以及三层内存发送暂存机制。原客户端的发送 FIFO 在取得服务端确认后释放，模型回复事件由另一条订阅链接收。尚未证实原版持久化可编辑发送队列或已发送聊天消息的原位编辑。Windows 适配器按对话串行完整模型生成，并明确区分未发送意图、已落本地消息和已发网络请求；初始化失败只回滚本次尚未分发的末尾消息，无法回滚时保留原消息身份供重试，避免重复追加。

0.4.0 通过 184 项后端/宿主检查和 78 项 Electron 桌面检查，覆盖引用、搜索分页与定位、删除清理、发送队列以及延迟确认期间的草稿保护。模型验证使用本机模拟，真实模型调用尚未验收。

0.5.0 新增独立的本地应用运行链：管理 HTML/React 源码、受限离线构建、独立预览与应用数据，以及模型创建、修改和构建工具。它通过 243 项后端/宿主检查与 106 项 Electron 桌面流程检查，覆盖真实 React 编译、页面执行、数据通道、导出、逐次审批、源码保存竞争及冲突。原客户端的 Space 前端协议已进一步恢复，但原编译服务的调用入口、输入输出和实现仍未知；本地运行时是独立实现选择。公开发布、远程托管及原版完整服务未完成。

原生定点分析还确认了 UI 调用 ID 与页面 generation 的双重匹配、通用调度的 HITL/权限顺序，以及原版整数参数类型编码。应用实际注册的外层 gate 另有放行型适配器，具体授权继续由内部路径研究，不能由通用分发器推断每个 OS 动作的授权行为。原生某个 UI broker 的 5 秒初始化值与 Web 声明的 6 秒不是统一超时行为的证明。

0.6.1 实现独立 Windows 持久调度器，恢复七类时间规则的本地执行、明确授权与 API 绑定、双份持久认领、只读工具限制、执行对话和后台托盘。311 项自动检查与 138 项实际 Electron 流程通过，包含到点触发、伪造写入拒绝、停止、资料撤回、导入暂停、模型创建计划，以及真实“退出→继续编辑”后继续调度和聊天。系统登录启动项与系统通知送达未在测试中修改或验收。

第六轮还恢复了原版任务列表、运行、删除、刷新、Goals 状态与创建聊天意图；原服务端任务创建 schema、调度引擎及重试算法仍未知。原生文件路径新增证据确认了应用目标状态检查与账户 generation 的 TaskLocal 匹配门，它与用户审批不同，完整权限语义仍未闭合。知识与技能进一步恢复了描述符、记忆检索、知识快照和连接授权的客户端链；`/MEMORY.md` 与 URI 记忆索引是两条独立接口，尚未证明自动同步，Windows 尚未实现对应服务。

## 尚待完成

第八轮进一步区分了原浏览器的三条路径：远端任务与控制租约通过加密 VNC 流传递画面和输入；本机关联浏览器另有显示、预览和按账户匹配的回调；Mac 原生命令又有独立权限状态。前端已追到任务创建、展示、接管、心跳、释放、停止、关闭、剪贴板及画面消费者。窗口列表按浏览器任务组织，不能将它当成完整浏览器标签页接口。原标签页操作、扩展、远端 VM 服务与本机执行层仍需恢复。

语音输入已追到录音、识别、草稿和普通聊天发送/取消的消费链。原生听写通过 composer/request/session 标识拒绝过期回调，浏览器适配器另有 16 kHz 和 24 kHz PCM 协议。停止审阅、丢弃和明确发送是不同意图；原生自动发送偏好也走普通聊天流程。实时通话则由 Mac 原生桥接接管，本包网页实际绑定的是空运行模块，不能据此声称恢复了 WebRTC 或原生媒体引擎。TTS 预览同样有独立的取消与播放链。用户的文本聊天模型不会自动具备语音识别能力。

连接器分析进一步分开了外部账户链接、本机应用权限、消息渠道和内置邮箱。邮箱重置保留结果不确定状态，测试邮件只将明确接受回执当作接受，且复用同一收件人的幂等键；两者均不能推导成已恢复投递服务。选定原生文件入口也已从账户代次捕获追到最终 TaskLocal 读取比较，两个不同 TaskLocal 通道仍分别记录。这是静态账户有效性检查证据，不替代路径授权、读写权限或用户审批。这一轮只增加逆向证据和进度说明，没有新增 Windows 执行能力。

0.7.1 接入独立本地知识链：长期记忆文档、知识条目与显式关键词索引、最多 50 份不可变快照、受限 Markdown 技能说明和内容版本授权，以及按聊天选择的配置。主机在排队、模型请求、工具调用、审批返回和结果保存前核对配置与授权；变更会停止旧上下文。380 项自动检查和 157 项 Electron 桌面流程已通过，包含实际模型工具创建/读取记忆、索引过期、资料隔离、后台路由变化时保留草稿，以及撤销技能后取消失效引用。验证使用本机模拟服务；原版可执行技能、语义检索与自动整理、连接器和同步服务仍未恢复。

第九轮从原生会话对象追到了具体 WebSocket 关闭调用（正常关闭码 1000、空原因）及 URLSession 取消，并独立核实 AVAudioEngine 停止、输入 tap 移除和节点清理。字段类型、对象偏移、选择器和实参都有原始字节支持；网页 `startVoiceCall` / `cancelVoiceCall` 到这套 S2S 会话的生产分发、音频闭包的实际调度仍未接通，不能把它视为完整原生通话实现。

0.8.1 新增 Windows 听写：明确开启麦克风、音量和时长、停止审阅、丢弃、识别后发送及显式自动发送偏好。识别期间改变草稿会保留新内容并改为审阅；范围、模型连接或知识授权变化会撤回旧会话。443 项自动检查与最终便携包的 178 项 Electron 桌面流程已通过，包含畸形地址密钥检查与隐藏窗口迟到启动保护，使用合成麦克风和本机模拟语音服务，未验证真实设备或外部 ASR。录音文件转写是独立适配，原实时流、系统快捷键、TTS 和通话仍待恢复。

第十轮进一步确认：原版 TTS 的消费者是声音选项试听，聊天音频组件读取已有文件，而不是将消息正文交给合成接口。试听有独立请求和播放代次；原生侧停止界面等待不等于取消宿主合成。聊天音轨可跨路由继续，普通消息删除也不直接清除已选音轨；全局关闭浮窗与停止播放同样不同。没有证明听写、试听和附件播放之间存在统一排他锁。

原生所选 WebKit 异步分发链中，开始/取消通话匹配后只走对象释放和返回分支。该结果限于这一条路径，不能推断整个应用都不支持通话。另已恢复独立 TTS 的 URL 构造、请求头/正文设置、URLSession 字节读取及错误回调支链；生产入口、认证、请求标识和成功音频回调仍未全部闭合。

0.9.0 接入声音试听与本地音频附件播放。声音供给使用用户自己的兼容服务返回完整 WAV，属于独立适配；没有把消息正文朗读或原服务端实现算作已恢复。488 项自动检查与最终便携包的 196 项 Electron 桌面流程全部通过，包含保存期间修改声音、样句或切换页面的竞争处理。验证使用本机模拟服务、静音合成音频与合成麦克风，未验证真实语音服务、麦克风或扬声器；启动至退出的运行文件摘要一致。

第十一轮闭合了原生 TTS 的选定成功生产链：网页的请求编号、声音和文本经异步任务进入真实服务；逐行事件解码为可选的类型与音频字段，音频经 Base64 解码后追加，完成标记或流结束后返回同一请求编号的 MP3 数据。请求编号的类型、任务捕获、栈复制和成功回调实参均有独立字节核验。认证目前只追到传入字符串用于 Bearer 请求头；它的来源、完整加密门禁、取消和超时策略仍待恢复。声音目录的筛选分页、保存声音配置、用户文件偏好读取与更新订阅也已有客户端证据，不能据此认定已恢复原声音服务。

原 Space 编辑器的元素注释分支已从页面点击追到普通聊天的隐藏上下文、当前对话选择、引用及清理行为。发送的是注释与元素文字、路径、视口和坐标；该分支没有生成截图。选择对象的本地元数据不能全部当作已发送的接口字段，注释也不直接写源码或调用编译器。设备上下文、文本选区、远端节点与编译服务仍有独立缺口。

0.10.0 接入隔离预览的元素选择、说明卡和普通聊天发送；保留已有草稿与附件，排队和恢复时保留页面上下文。开启助手后，所选应用可经单独确认的写入与构建完成迭代。539 项完整自动检查与最终便携包的 219 项 Electron 桌面流程全部通过，其中 23 项覆盖选区、异步恢复、路由切换、首次对话失败/重试及应用修改预览闭环；运行文件摘要从启动到退出保持一致。模型及语音仍使用本机模拟服务与合成设备。Windows 的私有消息通道、主机范围核对和界面布局为独立实现；尚未复刻原版完整 Space 协议。

第十二轮进一步区分了普通文本选区与真正发送的页面引用。原客户端每 500 毫秒处理的普通文本选区，以及 iframe 报告的实体、选区和视口，只写入本地设备上下文；所追踪的普通聊天路径没有将它们自动变成正文、隐藏提示或附件。真正闭合的是可见页面的 `metadata.active_panel`：它按浏览器、文件、购物、地点、想法、路由的优先级选取资源引用，Space 页面只提供应用种类和标识。聊天的局部文本复制与显式回复也走不同路径；唯一确认的浏览器截屏生产入口属于问题反馈上传，不是自动聊天截图。原生、生成页面及服务端的其他路径仍保留未知边界。

原生 TTS 的选定认证链也追到了 `AuthState.credential.authenticated.AuthCredentials.token`，作为 Bearer 凭据使用。其 56 字节任务捕获包含用户标识、账户代次、令牌代次与登录尝试；等待前后会核对账户、登录代次、用户标识和凭据，并比较等待所得令牌与重新获取的凭据。所选校验器没有比较令牌代次，不能据此宣称所有代次均被验证。令牌获取和持久化、完整目标地址策略、原生取消与超时仍有缺口。Web 的 SSE MP3 消费及回退客户端链已有证据；Windows 仍采用返回完整 WAV 的独立兼容适配，没有因此增加原版流式语音能力。

0.11.0 将本地应用改为与普通聊天并排的面板，较窄窗口可切换源码与预览。发送时由主机检查当前应用与对话范围，并附上应用名称和标识；这个引用本身不会自动上传源码、DOM 选区或截图。开启助手后，模型仍可能通过授权范围内的应用工具读取相关源码，写入和构建仍需逐次确认。排队消息保留原应用身份；恢复遇到新草稿、附件或引用时，原消息继续单独保留，避免混入另一应用的上下文。历史仅作为用户参考数据，删除应用不创造新的访问权限，删除用户消息会清除它的应用引用。566 项完整自动检查与最终便携包的 237 项 Electron 桌面流程全部通过，其中 18 项覆盖并排面板、当前应用引用、排队恢复和 900 像素窗口；运行文件从启动到退出无变化。自动检查还包含直接执行当前界面函数的六项异步准入回归。自有模型的文本适配、引用的本地历史保存和工具范围规则属于 Windows 实现；原服务对 `active_panel` 的持久化与使用方式尚未证明。
